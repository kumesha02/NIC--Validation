# NIC Validation System - Full Stack Development Prompt for Cursor IDE

## Project Overview
Build a complete NIC (National Identity Card) Validation System for Sri Lanka using React (Frontend) and Node.js (Backend) with Microservices Architecture and MySQL database.

---

## Backend Development Instructions

### 1. Initial Setup - Microservices Architecture

Create a Node.js microservices project with the following structure:

```
backend/
├── api-gateway/          # Port 8080 - Main entry point
├── auth-service/         # Port 8081 - Authentication & JWT
├── nic-validation-service/  # Port 8082 - NIC validation logic
├── file-processing-service/ # Port 8083 - CSV file handling
├── dashboard-service/    # Port 8084 - Analytics & metrics
├── report-service/       # Port 8085 - PDF/CSV/Excel generation
├── shared/               # Shared utilities, models, middleware
└── docker-compose.yml    # Docker configuration
```

**Technologies:**
- Express.js for all services
- MySQL with Sequelize ORM
- JWT for authentication (jsonwebtoken)
- Bcrypt for password hashing
- Multer for file uploads
- PapaParse for CSV parsing
- PDFKit for PDF generation
- ExcelJS for Excel generation
- Axios for inter-service communication
- Dotenv for environment variables
- Cors for cross-origin requests
- Express-validator for input validation


### 2. Database Configuration

Create MySQL database schema with Sequelize models:

**Models Required:**
1. **User Model** - id, username, email, password (hashed), createdAt, lastLogin, isActive
2. **UploadedFile Model** - id, fileName, originalName, totalRecords, validRecords, invalidRecords, uploadedAt, uploadedBy (FK), status
3. **NICRecord Model** - id, nicNumber, birthday, age, gender, fileId (FK), isValid, validationError, processedAt
4. **Report Model** - id, reportType, fileName, filePath, generatedBy (FK), generatedAt, status

**Relationships:**
- User has many UploadedFiles
- User has many Reports
- UploadedFile has many NICRecords (cascade delete)

### 3. Authentication Service (Port 8081)

**Endpoints:**
- POST `/auth/register` - Register new user (username, email, password)
- POST `/auth/login` - Login (username, password) → Returns JWT token
- POST `/auth/logout` - Logout and invalidate token
- POST `/auth/forgot-password` - Send password reset email
- POST `/auth/reset-password` - Reset password with token
- GET `/auth/verify` - Verify JWT token validity

**Requirements:**
- Hash passwords using bcrypt (salt rounds: 10)
- Generate JWT tokens with 24-hour expiration
- Include user id and username in JWT payload
- Implement middleware to verify JWT tokens
- Proper error handling for invalid credentials

### 4. NIC Validation Service (Port 8082)

**Core Validation Logic:**

Implement Sri Lankan NIC validation with these rules:

**Old Format (9 digits + V/X):**
- Example: 923456789V or 923456789X
- First 2 digits: Year (92 = 1992 or 1892 depending on century logic)
- Next 3 digits: Day of year (001-366 for males, 501-866 for females)
- Last 4 digits: Serial number
- Last character: V or X

**New Format (12 digits):**
- Example: 199212345678
- First 4 digits: Full year (1992)
- Next 3 digits: Day of year (001-366 for males, 501-866 for females)
- Last 5 digits: Serial number

**Validation Algorithm:**
1. Check format (regex validation)
2. Extract year, day of year, and serial number
3. If day > 500, subtract 500 and gender = FEMALE, else gender = MALE
4. Convert day of year to actual date (birthday)
5. Calculate age = current year - birth year (adjust if birthday hasn't occurred this year)
6. Return: { nicNumber, isValid, birthday, age, gender, errorMessage }

**Endpoints:**
- POST `/validate/single` - Validate single NIC
- POST `/validate/batch` - Validate array of NICs
- GET `/validate/formats` - Get supported NIC formats

### 5. File Processing Service (Port 8083)

**Endpoints:**
- POST `/files/upload` - Upload 4 CSV files simultaneously (multipart/form-data)
- GET `/files/list` - Get all uploaded files for logged-in user
- GET `/files/:id` - Get specific file details
- DELETE `/files/:id` - Delete file and associated records
- GET `/files/:id/records` - Get all NIC records for a file with pagination

**Requirements:**
- Accept exactly 4 CSV files (validate in middleware)
- Validate CSV format (must have headers: NIC, or NIC_Number)
- Process files asynchronously (use async/await properly)
- Parse CSV using PapaParse
- For each NIC in CSV:
  - Call NIC Validation Service
  - Save result to database (NICRecord model)
- Update file statistics (totalRecords, validRecords, invalidRecords)
- Implement batch processing (process 1000 rows at a time to avoid memory issues)
- Return processing status and summary

### 6. Dashboard Service (Port 8084)

**Endpoints:**
- GET `/dashboard/summary` - Get overall statistics
  - Total records count
  - Male count
  - Female count
  - Valid vs invalid records
  - Files processed count

- GET `/dashboard/charts` - Get data for charts
  - Gender distribution (for pie chart)
  - Age distribution by ranges: 0-18, 19-30, 31-50, 51-70, 70+ (for bar chart)
  - Records per file (for bar chart)

- GET `/dashboard/recent-uploads` - Get last 10 uploaded files

**Requirements:**
- Use Sequelize aggregate functions (COUNT, GROUP BY)
- Optimize queries with proper indexing
- Cache results for 5 minutes using in-memory cache
- Return formatted data ready for chart libraries

### 7. Report Service (Port 8085)

**Endpoints:**
- POST `/reports/generate` - Generate report (body: { type: 'PDF'|'CSV'|'EXCEL', fileId?: number })
- GET `/reports/download/:id` - Download generated report
- GET `/reports/list` - List all generated reports
- DELETE `/reports/:id` - Delete report file

**Requirements:**
- **PDF Generation**: Use PDFKit to create formatted PDF with table of NIC records
- **CSV Export**: Use PapaParse to convert data to CSV
- **Excel Generation**: Use ExcelJS to create Excel file with styling
- Include headers: NIC Number, Birthday, Age, Gender, File Name, Status
- Save reports to `/uploads/reports/` directory
- Store report metadata in database
- Implement streaming for large files

### 8. API Gateway (Port 8080)

**Requirements:**
- Proxy all requests to appropriate microservices
- Implement JWT authentication middleware
- Routes:
  - `/api/auth/*` → Auth Service (8081)
  - `/api/validate/*` → NIC Validation Service (8082)
  - `/api/files/*` → File Processing Service (8083)
  - `/api/dashboard/*` → Dashboard Service (8084)
  - `/api/reports/*` → Report Service (8085)
- Add CORS middleware
- Add request logging middleware
- Add error handling middleware
- Rate limiting (100 requests per 15 minutes per IP)

### 9. Shared Utilities

Create shared module with:
- Database connection configuration
- JWT middleware for authentication
- Error handling utilities
- Logger utility (Winston)
- Validation schemas (express-validator)
- Constants (error messages, status codes)

### 8. API Service Configuration

**Axios Setup (src/services/api.js):**
```javascript
import axios from 'axios';

const api = axios.create({
  baseURL: 'http://localhost:8080/api',
  timeout: 30000,
  headers: {
    'Content-Type': 'application/json'
  }
});

// Request interceptor - Add JWT token
api.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem('token');
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// Response interceptor - Handle errors
api.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      localStorage.removeItem('token');
      window.location.href = '/login';
    }
    return Promise.reject(error);
  }
);

export default api;
```

## Security Requirements

1. **Password Security:** Hash with bcrypt, never store plain text
2. **JWT Security:** Sign with strong secret, implement expiration
3. **Input Validation:** Validate all inputs on both client and server
4. **SQL Injection:** Use Sequelize ORM parameterized queries
5. **XSS Prevention:** Sanitize user inputs, use React's built-in escaping
6. **CORS:** Configure allowed origins properly
7. **File Upload:** Validate file types, limit file sizes, scan for malware
8. **Rate Limiting:** Prevent brute force attacks on login
9. **HTTPS:** Use HTTPS in production (configure in deployment)
10. **Error Messages:** Don't leak sensitive information in error messages

---

## Performance Optimization

1. **Database:** Add indexes on frequently queried columns (userId, fileId, nicNumber)
2. **Caching:** Cache dashboard statistics for 5 minutes
3. **Pagination:** Implement pagination for large datasets
4. **Lazy Loading:** Load components and routes lazily in React
5. **Image Optimization:** Optimize any images/icons used
6. **Bundle Size:** Code split React app
7. **API Calls:** Debounce search inputs, cancel previous requests
8. **File Processing:** Process large CSVs in batches (1000 rows at a time)
